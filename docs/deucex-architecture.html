Stack at a glance

A deliberately boring stack a team of three to five can run without a platform engineer. Every layer below names the choice, the reason, and the alternative that was weighed.

Player app
Next.js PWA + Capacitor
One web codebase, installable, offline queue. Capacitor wraps it for iOS and Android so background upload and native push work where Safari's PWA does not.
Weighed: React Native or full native. Doubles surface for a small team; nothing in the PRDs needs it.
Admin console
Second Next.js deployment
Same repository, own hostname (admin.deucex.ai), staff auth with mandatory passkey, a database role limited to what the console needs.
Weighed: a route group in the player app. Smaller, but a staff-auth bug would sit next to every player.
API and workers
Fastify on Fly.io
Owns everything with an external side effect: agent runs, webhooks, the actions module. Long-running processes for cron and queue workers.
Weighed: NestJS (more ceremony), Vercel functions (no long-running workers).
Database
PostgreSQL via Supabase
Row-level security for per-player isolation, check constraints for the money model, auth and realtime bundled.
Weighed: Neon or RDS plus a separate auth provider: less lock-in, a few more weeks of plumbing.
Jobs and schedules
pg-boss on Postgres
Six scheduled agents and every webhook run through one queue table with idempotency keys. No Redis to operate.
Weighed: BullMQ on Redis. The right next step if Postgres-as-queue ever becomes the bottleneck.
Object storage
Cloudflare R2
Voice notes and photos under player-scoped keys, no egress fees, S3-compatible. A daily worker deletes audio at seven days.
Weighed: S3. Egress cost and no reason to prefer it.
Models
Structured-output LLM · Whisper · TimesFM
Every agent call is JSON-schema constrained and Zod-validated. Whisper for transcription. TimesFM self-hosted for the Elite forecast.
Policy: providers used under no-training terms; the model behind each label is configuration, not copy.
Money and email
Stripe Billing + Connect Express · Resend
Card data never touches DeuceX (PCI SAQ A). Connect Express pays patrons out weekly. Resend sends patron updates.
Weighed: Paddle (no Connect equivalent for payouts).

System architecture

Two deployments face people, one service owns side effects, one database owns the truth. Everything to the right of the API is a vendor the platform can survive losing for a day.

The approval gate, as code structure

The product's central promise is that nothing leaves the app without a tap. Convention breaks under a rushed feature, so the gate is enforced by the shape of the code and a runtime check, not by review notes.

Failure is labelled, not hidden. A stale feed marks its field stale and the output schema always has a place to say a value was not refreshed, so a partial failure produces a labelled partial answer. A validation failure keeps last week's proposal visible with a banner. After three failed attempts the player is told the run did not complete.
Elite's Agent Studio cannot remove the gate. A player edits a small typed configuration object (cadence, tone, thresholds, escalation categories), never the system prompt or the pipeline. Schema validation, the gate and the five always-escalate categories are platform code outside any editable template.

Where MCP fits, and where it does not

The Model Context Protocol lets a model call tools through a standard server. Reviewed against this architecture, it earns its place in two areas and would damage a third.

Not in the scheduled agents. A run is one schema-constrained call on a pre-assembled bundle whose fields carry freshness tags, hashed into agent_runs with a fixed cost. Tool-calling would make cost variable (section on unit economics is already over the cap), empty the inputs hash of meaning, and move staleness labelling into the model. Ingestion, extraction and transcription are not agentic at all.
In building the platform. Supabase, Vercel, Stripe, Sentry and GitHub ship MCP servers. Claude Code uses them for migrations to a branch, logs and advisors, deployments and build logs, test-mode Stripe configuration, errors and pull requests. Writes go to branches and test modes only. No product change; a shorter build.
In operating the platform. One server to write beside E18: the console's reads and actions as MCP tools, under the console's rules (staff identity, role, a reason for deletions, comps, refunds, imports and switches, an admin_actions row with actor mcp:<admin>), every side effect through the actions module. "Find why three morning runs failed and retry them" becomes one request with the audit trail intact.

Plausible later: a read-only server grounding the Fan Agent (Release 2, only if the answer bank grows large), a constrained tool set for Agent Studio, and a player-scoped server so a player can ask their own assistant about their own money (Release 3, with a privacy review).

Pipeline, every push

Type-check, lint (including the rule that only packages/actions may import Stripe, Resend or the entry client), unit tests for every agent schema, the money-model acceptance test, migration dry-run against a branch, preview deploy. Merges to main deploy to staging; a tagged release deploys to production with migrations run first and a one-click rollback of the app (never of a migration; those are forward-only and additive).

Security and privacy

Isolation. Row-level security keyed on the authenticated player; the console uses a separate database role with an explicit grant list. Share-link tokens are 128-bit, checked on every request, revocation effective within a minute.
Identity. Players sign in by magic link with an optional passkey; no passwords exist to store, reset or leak. Staff sign in by magic link plus a mandatory passkey and never share accounts.
Money. Stripe holds all card data (PCI SAQ A). Bank connection is refused by design; reserves are typed by the player.
Lifecycle jobs. Audio deleted at transcript confirmation or seven days. Photos deleted after extraction. Account deletion after a 14-day cooling-off, executed by a job that also reaches backups and sub-processors and writes a completion record.
Compliance. Australian Privacy Act and APPs as baseline; GDPR for European players (export and erasure are real jobs, not policy text); standard contractual clauses behind every sub-processor; provider list disclosed to players under Data & safety.
Secrets and keys. Vendor keys in the host's secret manager, rotated on staff departure, never in the repository. Agents and LLM code have no vendor credentials at all.

Unit economics of model spend

PRD-00 caps average Pro model and API spend at 15 percent of the Pro price, A$7.35 a month. Summing each agent's own cost target at realistic usage gives about A$10.83, which is over the line. The chart is an estimate built from the contracts; the console's Money page will show the real figure from week one.

Where the money goes. Financial and Mindset Coach are over half the total because they run daily whether or not anything changed. Caching on the input hash (regenerate prose only when inputs move) plausibly cuts both by 30 to 50 percent.
The other levers. Model tiering (a small model for the Financial sentence, the brief comparison and menu translation; a large one for patron updates, outreach and the insight), batching the five Conditions briefs into one call, and per-tier rate limits on on-demand runs. Two to three weeks of scheduled Release 1 work, not an afterthought.

Risks, ranked by damage

1
Ranking and calendar data from three bodies
Tournament Agent, stage detection and Conditions all sit downstream of licences that are negotiated, not bought. Mitigation: start all three conversations in week one and ship the manual ingestion path as a first-class console feature so the product can soft-launch on hand-entered data.
2
The money model being subtly wrong
Currency switches, provisional-then-final rates, receivables in the wrong bucket. Mitigation: build the FX archive and locked-rate ledger before any money-touching agent, and make M-DATA-1's example an automated test.
3
The gate enforced by convention
Mitigation: the actions module, a lint rule on SDK imports, and a runtime check for an unconsumed approval, all in E12 before any agent sees real Stripe or Resend credentials.
4
Model spend over the 15 percent ceiling
The contracts' targets sum to A$10.83 against A$7.35. Mitigation: caching, tiering and batching as scheduled Release 1 work; the console alerts at 80 percent of cap from week one.
5
Stripe Connect Express country coverage
Players are worldwide; some countries are unsupported for payouts. Mitigation: check the early player list against Connect's country table before promising a launch date; have a manual payout fallback.
6
iOS background upload and push through a wrapper
Capacitor covers it; App Store review of thin wrappers is the residual risk. Mitigation: ship real native affordances (share sheet, push, background upload) so the app is not a webview with an icon.
